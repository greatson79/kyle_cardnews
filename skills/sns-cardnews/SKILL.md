# SNS Card News — 대표 오케스트레이터

설교의 핵심을 **시각적으로 소비 가능한 SNS 콘텐츠**로 변환하는 스위트의 단일 창구다.
사용자는 이 스킬에만 명령한다. 하위 스킬을 직접 부르지 않는다.

## 스위트 구성

| 스킬 | 역할 | 호출 시점 |
|------|------|----------|
| `sns-cardnews-context` | 설교 자료에서 CMT·FCF·HP 자동 추출 | 컨텍스트 불완전 시 |
| `sns-cardnews-design` | 슬라이드별 디자인 브리프 | 항상 (3단계) |
| `sns-cardnews-copy` | 10장 텍스트 + 캡션 + 카톡 | 항상 (4단계) |
| `sns-cardnews-build` | HTML 조립 + PNG 캡처 | 항상 (5단계) |
| `sns-cardnews-verify` | 독립 검증 (빌더와 분리) | 항상 (6단계·필수) |

하위 스킬은 전부 `disable-model-invocation: true` — 이 대표 스킬의 지시로만 실행된다.

## 실행 절차

### 0. 준비 확인
- `config/brand-guide.md`가 채워져 있는가? 미설정이면 **Implications 질문**: 교회명·색상
  방향(제시안 3개)·해시태그를 물어 config에 기록 후 진행. 기본값 임의 확정 금지.
- `config/logo.png` 부재 시: 로고 없이 텍스트 마크로 진행할지 질문(실물 자산은 사용자 제공).

### 1. 입력 분류
| 입력 형태 | 처리 |
|----------|------|
| sermon-context.md (CMT·FCF·HP 완비) | 바로 2단계 |
| 설교 원고 전문 / 전사 / 부분 요약 | `sns-cardnews-context` 호출 → 추출 결과를 사용자에게 1회 확인 |
| 아무것도 없음 | 최소 정보(본문·핵심 메시지) 질문 — 단 질문은 1회로 모아서 |

### 2. Implications 질문 (해당 시에만)
결과를 가르는 선택지가 있으면 **진행 전에 모아서 한 번에** 질문한다:
- 표지 제목 복수안(2~3안) 택1
- 디자인 방향 분기(브리프가 2안 이상 낼 때)
- 톤 조정(기본: 경건하되 접근 가능)

### 3~5. 하위 스킬 순차 호출
design → copy → build. 각 산출물은 출력 폴더에 저장.

### 6. 독립 검증 (생략 불가)
`sns-cardnews-verify` 호출. 판정 기준:
- FAIL 항목 발생 → 해당 담당 하위 스킬로 되돌려 수정 → 재검증 1회
- 재검증도 FAIL → 사용자에게 정직 보고(무엇이 왜 실패했는지) — 통과한 척 금지

### 7. 응답 형식 (강제)

```markdown
## 발동·분류
(입력 유형·적용한 사이클·Implications 질문 여부)

## Orchestration Trace
1. sns-cardnews-context (HH:MM) — 사유
2. sns-cardnews-design (HH:MM)
...

## 하위 스킬 산출물
### context: ...
### design: ...
(각 스킬별 산출 요약 + 파일 절대경로)

## Synthesis (마스터 통합)
(최종 결과 요약·검증 판정·사용자가 할 일)
```

인라인으로 하위 스킬을 "시뮬레이션한 척"만 하고 넘어가는 것은 금지 — 실제 호출과 산출
파일이 trace와 1:1 대응해야 한다.

## 절대 규칙

- **품질 우선**: 10장 중 8장만 만들고 끝내지 않는다. 실패는 정직하게 보고한다.
- **환각 금지**: 성경 인용·사실 주장은 verify를 통과해야만 산출로 인정된다.
- **규격 정본**: 10장 · 1080×1350(4:5) · 슬라이드 6 복음 비트 불가침(브리프가 명시적으로
  다른 장을 지정한 경우 그 장) · 마지막 장 로고.
